1. Initialisation de l'Environnement et Sécurisation SSH

L'installation s'effectue idéalement via une interface en ligne de commande (CLI) pour garantir l'intégrité du workflow.

1.1 Installation de Git

Exécuter la commande suivante pour installer le moteur de versioning :

# Sur Windows (via winget)
winget install --id Git.Git -e --source winget

1.2 Sécurisation par Clé RSA

Générer une paire de clés SSH pour authentifier les transactions avec les dépôts distants (GitHub/GitLab) :

# Création de la clé RSA 4096 bits
ssh-keygen -t rsa -b 4096 -C "votre.email@exemple.com"

# Extraction de la clé publique pour configuration profil
cat ~/.ssh/id_rsa.pub

Note : La clé publique doit être enregistrée dans les paramètres SSH de votre hébergeur de code.

1.3 Installation de Node.js et de l'Agent CLI

# Déploiement de l'environnement d'exécution
# (Sur Windows via winget)
winget install --id OpenJS.NodeJS.LTS -e --source winget

# Installation globale de l'interface de pilotage (exemple pour Gemini)
npm install -g @google/gemini-cli

2. Déploiement du Noyau Applicatif

Une fois l'environnement sécurisé, procéder au déploiement des scripts et du moteur de rendu :

# Clonage du répertoire
git clone https://github.com/SamyBelm/AutoRechercheAlternance.git
cd AutoRechercheAlternance

# Initialisation des dépendances et du moteur PDF Playwright
npm install
npx playwright install chromium

3. Standardisation du CV (Format Markdown)

Le système utilise un fichier cv.md comme source de données canonique. Ce format permet une analyse granulaire des compétences techniques.

Directives de conversion du CV :
  • Structure : Utiliser des titres hiérarchisés (# pour le nom, ## pour les sections).
  • Typographie : Utiliser le gras (**) pour les technologies clés.
  • Listes : Préférer les puces (*) pour les descriptifs de postes et les compétences.
  • Emplacement : Le fichier doit impérativement être nommé cv.md à la racine du projet.

4. Configuration de la Veille et des Portails

Le fichier portals.yml centralise les sources d'opportunités. Il est paramétré pour interroger directement les APIs des principaux portails technologiques.

Infrastructure de Scan :
  • Sources : Greenhouse, Ashby, Lever (Flux directs).
  • Filtres : Personnalisables via les sections title_filter.
# Configuration des filtres de pertinence
title_filter:
  positive: ["Software Engineer", "Systems Administrator", "DevOps"]

5. Paramétrage des Préférences Utilisateur

Le système peut être personnalisé via les fichiers de configuration pour valoriser votre profil :

  • Profil (config/profile.yml) : Définition des informations de contact et des rôles cibles.
  • Modes (_profile.md) : Personnalisation du ton et de la narration pour les lettres de motivation.

6. Procédures d'Exploitation Quotidienne

  • Analyse de Poste : Soumission de l'URL ou du descriptif dans l'interface CLI pour évaluation.
  • Veille Automatique : Lancement périodique des commandes de scan via les filtres définis.
  • Reporting : Suivi des indicateurs de performance dans le fichier applications.md.
